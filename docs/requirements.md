# Требования FitnessIT (MVP)

Роли: **клиент** (студент KBTU), **тренер**, **администратор**.

## Must (MVP)
| ID | Требование | Где реализовано | Тест |
|---|---|---|---|
| FR-01 | Регистрация по email `@kbtu.kz`, пароль 8–128 символов | `auth.register` | `test_register_*` |
| FR-02 | Вход и выход, одинаковая ошибка для неверного email и пароля | `auth.login/logout` | `test_login_errors_*` |
| FR-03 | Три роли; страницы `/admin` и `/trainer` закрыты для других ролей (403 даже по прямой ссылке) | `roles.py` | `test_role_separation` |
| FR-04 | Расписание на ближайшую неделю: вкладки по дням недели, прошедшие занятия видны, но запись на них закрыта | `schedule.render_schedule` | `test_schedule_and_filters`, `test_schedule_has_seven_day_tabs` |
| FR-05 | Запись клиента на занятие со свободным местом | `booking.book` | `test_book_and_cancel` |
| FR-06 | Запрет двойной записи и записи на пересекающиеся по времени занятия | `booking.book`, `UNIQUE(user_id, slot_id)` | `test_duplicate_rejected`, `test_overlap_rejected` |
| FR-07 | Запрет записи на начавшиеся, прошедшие и отменённые занятия | `booking.book` | `test_past_and_cancelled_slot_rejected`, `test_past_slot_visible_but_cannot_be_booked` |
| FR-08 | Контроль вместимости без гонок (одна транзакция `BEGIN IMMEDIATE`) | `booking.book` | `test_full_slot_rejected` |
| FR-09 | Отмена записи не позднее чем за 2 часа до начала | `booking.cancel` | `test_late_cancel_rejected` |
| FR-10 | Страница «Мои записи» | `schedule.my` | — |
| FR-11 | Администратор создаёт и отменяет занятия; у занятия есть зал; тренер и зал не могут быть заняты двумя занятиями одновременно | `staff.create_slot/cancel_slot` | `test_admin_creates_and_cancels_slot` |

## Should
| ID | Требование |
|---|---|
| FR-12 | Тренер видит список записанных на свои занятия |
| FR-13 | Администратор видит записанных на любое занятие |
| FR-14 | Защита: CSRF, лимит попыток входа и регистрации, хеширование паролей |
| FR-15 | Фильтры расписания: тип занятия, тренер, зал, дата, «только со свободными местами» |

## Пять проверок при записи (FR-05…FR-08)
1. Занятие существует и не отменено.
2. Занятие ещё не началось.
3. Нет активной записи на это занятие.
4. Нет пересечения по времени с другими записями клиента.
5. Есть свободные места.

Все пять проверок и вставка выполняются в одной транзакции. При любой ошибке выполняется `ROLLBACK`.
